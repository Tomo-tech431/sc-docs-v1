== OBC Interface (CON1)
CON1 is the connection interface with the OBC. +

Installed connector: SEAM-40-02.0-S-10-1-A-K-TR (Samtec)

== BPD Power Supply Interface (CON2)
CON2 is an interface capable of supplying power to the Versal's Battery Power Domain (BPD). +
The BPD encompasses the Real Time Clock (RTC) and Battery Backup RAM (BBRAM). +
The RTC and BBRAM typically operate on the voltage (VCCAUX_PMC_SMON) generated within the OBC, but if the main power of the OBC is disconnected, they are maintained or retained by the voltage supplied from CON2.

|1 |VCC_BATT_IN |Power |VCC_BATT_IN |Power supply (VCC_BATT_IN)
|2 |GND |Power |VCC_BATT_IN |Ground
|===

== Versal / IGLOO2 Debug Interface (CON6)
CON6 is the debug interface for Versal and IGLOO2. +
It is equipped with an FTDI IC, allowing the selection of the following debug methods:

- Versal FPGA JTAG
- Versal APU/RPU Console
- IGLOO2 Safety Processor Telemetry/Telecommand

Additionally, the Versal high-speed serial communication signal GTYP is connected to CON6 via a bidirectional high-speed multiplexer, enabling debugging with the Versal SmartLynq+ HSDP.

=== Versal FPGA JTAG
This is the Versal FPGA JTAG interface. +
When the jumper sockets inserted in JP13-JP18 are switched to the "FTDI" silkscreen side, it connects to Channel A of the FTDI IC and becomes available for use.

=== Versal APU/RPU Console
This is the console for the Versal APU/RPU. +
By switching the jumper sockets inserted in JP19-JP24, the serial communication signals mapped to the Versal UART are connected to the FTDI IC and become available for use. +
Versal UART0 is connected to Channel B of the FTDI IC, and UART1 is connected to Channel C. +
There are two types of serial communication signals: Versal LPD MIO and Versal HDIO. Since they are independent, even if one serial communication signal is used in a test, the other can be used as a console.

[width="100%",cols="1,1,1,1",options="header",]
|===
|FTDI IC Channel |Mapping |I/O |Select JP
.2+|B .2+|UART0 |Versal LPD MIO |JP19~JP21: 1-2 |Versal HDIO |JP19~JP21: 2-3
.2+|C .2+|UART1 |Versal LPD MIO |JP22~JP24: 1-2 |Versal HDIO |JP22~JP24: 2-3
|===

=== IGLOO2 Safety Processor Telemetry/Telecommand
Using the IGLOO2 UART, it is possible to monitor via Telemetry signals from the OBC or change modes via Telecommand signals to the OBC. +
When the jumper sockets inserted in JP25-JP29 are switched to the "FTDI" silkscreen side, it connects to Channel D of the FTDI IC and becomes available for use.

=== Versal SmartLynq+ HSDP
Using the Versal HSDP (High-Speed Debug Port), high-speed debugging and tracing are possible via the AMD SmartLynq+ module. +
It becomes available for use by inserting a jumper socket into JP34.

== Versal Reserve Interface (CON7)
Versal PMC MIO 1 is connected to CON7. +
The MIO connected to CON7 is used to control the communication direction when a level shifter is provided between it and the microSD card interface. +
Since the Dev Board uses a level shifter capable of bidirectional communication, this function is unnecessary, hence it is designated as Reserve.

== microSD Card Interface (CON8)
CON8 is an interface where a microSD card can be inserted. +
In the early stages of development, it is assumed that the software for booting will be written to and used from a microSD card instead of the Flash memory or eMMC on the OBC.

== USB2.0 Interface (CON9)
CON9 is an interface that allows the OBC to be used as a USB 2.0 host. +
The VBUS, which is the power supplied from CON9, uses +5V generated from the main power of the Dev Board and routed through a load switch. +
VBUS complies with USB 2.0.

== Gigabit Ethernet Interface (CON10)
CON10 is a Gigabit Ethernet interface with an RJ45 type jack. +
By porting the Linux OS to the Versal APU, remote login to the OBC becomes possible. +
When the connection link is established, the green LED mounted on CON10 lights up. +
During communication, the yellow LED also mounted on CON10 blinks. +
When using CON10, select JP38-JP41 so that the power domain of the Versal LPD MIO is 1.8V or higher.

== Interface for FMC Module Connection (CON11)
CON11 is an interface capable of connecting a commercially available FMC module for the purpose of evaluating the high-speed serial communication signals of Versal PL or IGLOO2. +
The expected FMC modules for connection are as follows:

- PCIe Gen3 x8 FMC Module by iWave (iW-FMC-PCIe-I2)
- M.2 M-key Stack FMC by opsero (OP073)
- RPi Camera FMC by opsero (OP068)
- FMC XM105 Debug Card by AMD (HW-FMC-XM105-G)

Installed connector: ASP-134486-01 (Samtec)

== Versal MIO Expansion Interface (CON12)
CON12 is an interface for bringing out the unused Versal MIO signals to the outside. +
However, some LPD MIOs can be connected to circuits on the FTDI, CAN, or CON11 (Interface for FMC Module Connection) by jumper settings.

Please note that the Versal LPD MIO connected to Pins 1-8 of CON12 can be connected to circuits other than CON12 using jumper sockets. +
The power supply (VDD_B502) connected to CON12 also serves as the power domain for the Versal LPD MIO, and its voltage can be selected with JP38-JP41. +
In addition, a load switch is provided for VDD_B502, so that if the main power of Versal is disconnected, it will reliably disconnect the power to Versal Bank 502 as well. +
Versal PMC MIO 0 and Versal PMC MIO 1, connected to Pins 13-14 of CON12, have a fixed power domain of 1.8V, so the power domain is converted to VDD_B502 via a level shifter (IC27) to match the Versal LPD MIO. +
Therefore, please note that you must switch JP47-JP48 according to the communication direction of Pins 13-14.

== Versal HDIO Expansion Interface (CON14)
CON14 is the interface where the Versal HDIO is connected. +
It is divided into 3 blocks of 12 pins each, separated by NC pins, and the row of each block corresponds to the PMOD pinout. +
When multiple PMODs are inserted into CON14, NC pins are placed in between so that the PMODs do not interfere with each other. +
The power supply (VDD_B302) connected to CON14 also serves as the power domain for the Versal HDIO, and its voltage can be selected with JP49-JP52. +
A load switch is provided for VDD_B302, so that if the main power of Versal is disconnected, it will reliably disconnect the power to Versal Bank 302 as well.

== IGLOO2 MSIO (Bank 5) Expansion Interface (CON15)
CON15 is the interface where the IGLOO2 MSIO (Bank 5) is connected. +
Like CON14, it is divided into 3 blocks of 12 pins each, and the row of each block corresponds to the PMOD pinout. +
Similar to CON14, when multiple PMODs are inserted, the blocks are separated to prevent PMODs from interfering with each other. However, due to the large number of MSIOs, MSIOs are also connected between the blocks, which were NC pins in CON14. +
CThe power supply (VDD_M2GL_B5) connected to CON15 also serves as the power domain for the IGLOO2 MSIO (Bank 5), and its voltage can be selected with JP53-JP56. +
However, since the main power of IGLOO2 is linked to the main power of the Dev Board, unlike VDD_B502 and VDD_B302, no load switch is provided for VDD_M2GL_B5.

== Dev Board Main Power Supply Interface (CON16)
CON16 is the interface for supplying main power to the Dev Board. +
It uses a DC jack, and the plug specifications of the compatible AC adapter are an outer diameter of 5.5mm, an inner diameter of 2.1mm, center positive. +
When using CON16, do not apply voltage to CON20.

Installed connector: PJ-002AH (Same Sky)

== USER LED Control Interface (CON17)
CON17 is an interface that can control the LEDs (USER LED) that users can optionally use. +
One LED can be controlled for each pin. +
When a High-level signal is input to a pin, the LED lights up, and when a Low-level signal is input, it turns off. +
Be careful not to apply a voltage of 6V or higher to each pin.

[width="80%",cols="1,1,1,1",options="header",]
|===
|Pin Number |Pin Name |I/O |Description
|1 |ULED1 |Input |Can control LED6
|2 |ULED2 |Input |Can control LED7
|3 |ULED3 |Input |Can control LED8
|4 |ULED4 |Input |Can control LED9
|===

== IGLOO2 RS422/485 Interface (CON18)
CON18 is an interface capable of communicating with the IGLOO2 UART using the RS-422/RS-485 standard. +
Communication becomes possible by switching the jumper sockets inserted in JP25-JP29 to the "RS422" silkscreen side and connecting a device compatible with the RS-422/RS-485 standard to CON18. +
JP30-JP33 enable switching to half-duplex or full-duplex communication methods, as well as switching the termination resistor. +
Also, communication signals can be observed at CON3.

|2 |RS422_TXM |Output |VDD_3V3_C |Negative side signal of differentially converted IGLOO2 UART_TX
|3 |RS422_RXP |Input |VDD_3V3_C |Positive side signal of differentially converted IGLOO2 UART_RX
|4 |RS422_RXM |Input |VDD_3V3_C |Negative side signal of differentially converted IGLOO2 UART_RX
|5 |GND |Power |VDD_3V3_C |Ground

== CAN Interface (CON19)
CON19 is the interface for CAN communication. +
The Versal LPD MIO that can be mapped to CAN0 is converted to a differential signal by a CAN Transceiver and connected to CON19. +
It can be used by inserting a jumper socket into JP42-JP44, but please note that the MIO used here also branches to CON12. +
CAN communication can be terminated by inserting a jumper socket into JP45-JP46. +
When using CON19, select JP38-JP41 so that the power domain of the Versal LPD MIO is 1.8V or higher.

[width="100%",cols="1,1,1,1,1",options="header",]
|===
|Pin Number |Pin Name |I/O |Power Domain |Description
|1 |CAN_CANL |In/Out |- |CAN L signal
|2 |CAN_CANH |In/Out |- |CAN H signal
|3 |GND |Power |- |Ground
|===

== Dev Board Main Power Supply Interface (CON20)
CON20, like CON16, is an interface for supplying main power to the Dev Board. +

When using CON20, do not apply voltage to CON16.
